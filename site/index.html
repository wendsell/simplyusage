SimplyPrint × Bambu Lab

Every gram counted.

SimplyPrint only deducts filament for prints it starts. Send a job straight from Bambu Studio or Orca and your spools never move.

simplyusage reads the real per-color usage from each finished print and deducts it from the spool in each AMS slot that printed it.

Why you'd want this

You like SimplyPrint for what it does around the printer. You just don't slice there.

You slice on the desktop

Bambu Studio or Orca is where your tuned profiles, painted multi-color models and MakerWorld projects live. You hit Print there and send it over LAN. SimplyPrint's web slicer and queue rarely get touched.

SimplyPrint doesn't count those prints

It only deducts filament for prints it starts. Jobs from your desktop slicer show up in its history with 0 g used, so your spool weights quietly drift from reality.

Drift costs you prints

The inventory says 600 g left on a spool that's nearly empty. You find out when a long print runs out halfway, or when you reorder the wrong colors.

Keep both

Slice and send however you like. simplyusage makes SimplyPrint's spool weights match what's actually on the spool.

You don't need it if you start all your prints from SimplyPrint, since it already counts those.

How it works

It runs next to the SimplyPrint bridge and works from what the printer already reports, so nothing changes about how you print.

Print starts

The printer announces which AMS slot feeds each filament in the file.

Print ends

simplyusage fetches the job's .3mf from the printer's SD card and reads the grams per color.

Already counted?

If SimplyPrint started the print and logged usage itself, the job is skipped.

Spools updated

Each slot's spool in SimplyPrint gets its remaining weight lowered by what was used.

What you get

Multi-color, per slot

Every filament in the print is matched to its AMS slot and deducted from that slot's spool.

Real numbers

Usage comes from the slicer data in the print file, including color-change flush and the prime tower.

Failed prints too

Cancelled or failed prints are deducted by how far they got.

Never twice

A ledger records every job, so restarts and SimplyPrint's own prints never double count.

No extra connections

Reads printer reports from the bridge's logs. Bambu printers allow only a few LAN clients, and this doesn't take one.

Runs where the bridge runs

One small container for amd64, arm64 and arm/v7. A Raspberry Pi is plenty.

Quick start

The image is on GitHub's container registry:

docker pull ghcr.io/wendsell/simplyusage:1

Setup takes about fifteen minutes. One step protects the SimplyPrint bridge from losing its printer list when its container is recreated, so follow the guide rather than winging it.
